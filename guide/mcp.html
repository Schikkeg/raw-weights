    🌐 Remote SSE & OAuth

    Standard I/O (stdio) works locally, but Server-Sent Events (SSE) host servers remotely. MCP natively handles OAuth 2.0 handshakes securely.

    🔄 Sampling

    Reversing the flow. A remote server can request LLM inference (completions) from the connected client, borrowing its intelligence without its own LLM.

    🧩 Composability

    Client and Server are logical separations. Sub-agents can act as both, creating deep hierarchical workflows and routing data securely.

    👁️ Observability

    The protocol does NOT enforce observability. Server builders must actively expose ergonomic metadata and logging for security.

    🛠️ In the Trenches: Java Server Lessons

    Building from scratch teaches harsh realities of protocol strictness. Lessons to save 10 hours of debugging:

    • ✓
      A. The "Jackson War" is Real
      The MCP Java SDK includes Jackson 3 hooks, but stacks like Javalin/Spring use Jackson 2. Manually exclude the mcp-json-jackson3 adapter in Maven to avoid NoSuchFieldError crashes.
    • ✓
      B. Local vs. Cloud Connectivity
      Stdio is easy. Cloud web LLMs require a persistent SSE HTTP stream (ctx.req().startAsync()) and a public tunnel (like ngrok) to bypass localhost limits.
    • ✓
      C. The CORS "Header" Trap
      Allowing the URL in CORS isn't enough. You must explicitly expose the mcp-session-id header or the browser blocks the handshake.
    • ✓
      D. Stdio is "Silent or Die"
      In Stdio, System.out is the data pipe. A single println("Hello World") corrupts the JSON-RPC. Use System.err for all logging.
    • ✓
      E. Schema Strictness"
      LLMs are picky. Even if optional, adding List.of("topic") to the required fields in your JSON schema makes tools significantly more reliable to invoke.

Signal vs Noise Lab — 3 Compression Methods

Think of a college group chat after exam results — 80% noise, 20% signal. A retrieved chunk has the same problem: the fact you need is buried in filler. Pick your filter below and see what survives — and what the model never needed to read.

Summarize — when?

Long chunk, qualitative content. Losing some nuance is acceptable. Best for narrative passages.

Compress — when?

Many chunks, speed matters. Drop stop-words and filler. Preserves almost all facts telegraphically.

Graph RAG Lens — Flat vs Rich Retrieval

Vector search finds semantically similar chunks. Graph RAG finds chunks AND traverses the relationships around them. Same query — radically different context depth. Toggle to compare.

Graph structure

Context passed to LLM

Use Graph RAG when you can answer YES to all three:

✓Your data has named entities that connect to each other (people, companies, products)
✓A query answer requires traversing 2+ hops across relationships
✓You can tolerate the upfront cost of defining a graph schema (Neo4j/Cypher)

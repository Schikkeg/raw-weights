The Key Idea

The Signal That Makes It Human

One concept from the session unlocks everything else. Voice agents used to sound robotic because emotion got lost at every stage handoff. The fix is a small token — an audio tag — that carries feeling through the entire pipeline as plain text.

👂 STT Speech-to-Text Detects emotion → outputs tags
→
🧠 LLM Language Model Reads tags, generates new ones
→
🔊 TTS Text-to-Speech Tags → sounds like a human

The STT model doesn't just transcribe words — it adds tags like [ laughing ] [ background music ] when it detects them. The LLM learns to pass those tags through and generate new ones in its response. The TTS V3 model reads [ excited ] [ whispering ] [ French accent ] and changes how it sounds accordingly. No extra code at any step — the signal is just text.

Why this matters for builders: LLMs are naturally good at copying patterns. Once you understand that audio tags are just text tokens in the prompt, you can instruct your agent to generate them, suppress them, or mirror them from the user's input. Emotion becomes a first-class parameter in your system prompt, not an afterthought.

Which Build Path Is Right for You?

ElevenLabs offers three distinct integration patterns. The right one depends entirely on whether you already have a working agent or are starting from scratch.

Existing Agent
Speech Engine
You already have a chatbot or RAG pipeline and just need voice added on top. You keep your LLM. ElevenLabs handles STT, TTS, and turn-taking. When a response is needed, ElevenLabs sends you the transcript — you reply with text — ElevenLabs speaks it.
Best for: teams with working RAG agents, LangGraph pipelines, or existing LLMs who want voice without rebuilding.
Starting Fresh
Full Agent
Build natively inside the ElevenLabs agent platform. You get the full dashboard: system prompt, voice, LLM choice, procedures, tools, branching, topic discovery, and coaching — all in one place. Turn-taking and audio tag routing happen automatically.
Best for: new voice agent projects where you want the full ops layer (procedures, branching, testing) out of the box.
Targeted Use
TTS / STT APIs
You only need one direction — either speaking text or transcribing audio. Call the TTS or STT API directly. Useful for podcast enrichment, audio generation pipelines, or transcription workflows where you don't need a full conversational agent.
Best for: audio production pipelines, content enrichment, batch transcription — not real-time voice agents.
The SDK options: Python, JavaScript, WebSocket, WebRTC, React Native, Kotlin. If your platform runs any of these, you can embed an ElevenLabs voice layer. For platforms like Salesforce, an active partnership exists but the native integration is still developing — WebSocket is the current path.
Real World

One Use Case, Four Questions

During the Q&A, an attendee was building a voice layer on top of a multi-agent system for a regulated industry. They asked four connected questions that added up to a complete enterprise deployment challenge — we went deep on all four. Each one revealed something the demos don't show.

The problem: your backend needs a human to approve before the agent can act

A common multi-agent pattern — especially in LangGraph — is to pause before any write action and wait for a human to click Approve. In a chat interface, the user just sees a loading state. In a live voice call, that same pause creates dead silence on the line, and the webhook times out.

⏱ Timeout — call drops
What works — async tool calls
Agent fires tool
→
Agent keeps chatting
 No blocking. No silence.
Human approves (whenever)
→
Backend returns
→
New tools / knowledge unlock live

ElevenLabs supports asynchronous tool calls — the agent fires the webhook and carries on the conversation without waiting. When the backend eventually returns, the platform injects new capabilities into the live call: new tools become available, a knowledge-base entry gets added to context. The agent picks it up naturally — "I can now see your account details" — with no awkward pause.

Practical example: A 2-minute identity verification flow. Agent fires the auth webhook async, chats normally in the meantime. Once verification completes, the agent gains access to account-level tools it didn't have before — and mentions it naturally in conversation.

The problem: verifying caller identity before (or at the start of) the conversation

Regulated industries need to know who is calling before the agent does anything sensitive. The question was whether voice recognition, emotion detection, and STT could handle authentication in the brief window before the agent starts speaking. The answer: yes — with the right pattern.

The OTP approach converts a traditionally robotic step (DTMF tones, "enter your PIN on the keypad") into a natural voice conversation. STT handles the number extraction. The agent just asks, listens, and verifies — no keypad required.

The problem: your users speak different dialects of the same language

Accents and dialects aren't the same problem. Accents are handled within a language model. Dialects — especially those with completely different pronunciation — are treated as separate sub-languages. The gap in coverage comes down to one thing: how much training data exists on the internet for that dialect.

Well Supported
Major dialect pairs

Portuguese vs Brazilian Portuguese. Standard Spanish vs Latin American Spanish. These are modeled as separate sub-languages but share training data intelligence — coverage of one helps the other.

Data-limited
Mandarin vs Cantonese

Similar grammar, completely different pronunciation. Mandarin has enormous training data; Cantonese has far less. Quality gap is a data problem, not an architecture one — the model can only learn what it's seen.

Broad Coverage
Indian languages

9–10 Indian languages are supported, covering 99% of the world's population. Specific regional dialect coverage within each language was not detailed in the session.

Unsolved
Low-resource dialects

"A bit of an unsolved problem." If a dialect lacks internet training data, architecture can't compensate. PVC (Professional Voice Clone) is the best mitigation for accent-critical deployments — it learns from your specific audio, not general data.

How to configure it: Dialects aren't auto-detected mid-call. You specify which languages and sub-languages your agent supports in the dashboard. For accent-sensitive use cases, the audio tag system allows the LLM to inject accent directives into TTS — but only works well when the dialect is within the model's training coverage.

The problem: proving your voice agent behaves correctly when regulators ask

Regulated industries can't just deploy and hope. Conversations that change account data, offer credits, or handle complaints need to be auditable — adversarially tested and human-validated before going live. The session covered how ElevenLabs approaches this with a specialist audit partner.

10,000
Phase 1 — Automated Adversarial Testing

Synthetic agent callers run nefarious scenarios: prompt injection, aggressive language, attempts to make the agent contradict its policy or say something it shouldn't. Fully automated. Measures whether the agent stays on-policy under pressure.

100
Phase 2 — Human Red-Team Testing

Real humans call the agent with fabricated but realistic scenarios. Each person is given a character and a goal. Human raters score whether the agent handled each call correctly, helpfully, and within policy.

The two phases answer different questions. Phase 1 asks: can this agent be manipulated? Phase 2 asks: does this agent actually help real people? Both are needed. Neither replaces the other. The output is a formal audit report — the kind a regulated industry can present to a compliance function.

On AI safety more broadly: ElevenLabs has a large dedicated AI safety team. Their primary concern is voice fraud — the risk that someone clones a real person's voice and uses it for a scam call. When emotion tags like "crying" are tested in a suspicious context, the system refuses to generate the audio. Child protection and non-consensual cloning detection are active areas. PVC (Professional Voice Clone) requires identity verification before the clone can be created.
Decision 4

Before You Ship — Three Practices That Actually Matter

The session was direct about what separates a demo from a production agent. Three practices came up repeatedly as non-negotiable once you have real call volume.

01

Procedures, not one giant prompt

Instead of a single system prompt covering every edge case, write trigger-based procedures — each one loads only when its trigger fires. The agent's context stays lean, the LLM stays focused, and your costs stay predictable.

→ The industry is moving from monolithic prompts to SOPs + Skills. Start here before you have 5,000 tokens in a single prompt.
02

Branch before you commit

Every configuration change — new LLM, new voice, new procedure — should go to a traffic branch first. Send 3% of real calls to the experiment. Measure sentiment, call duration, and resolution rate before promoting. Never change main directly.

→ Run synthetic tests (10–50 calls) before even the 3% slice. Voice agents are non-deterministic; one pass proves nothing.
03

Find where sentiment drops

Topic Discovery clusters your past conversations semantically and groups them. Find the clusters where sentiment trends DOWN over the call's duration — those are the scenarios your agent is actively making worse. Build procedures specifically for those.

→ Once you have volume, this can be automated: point an agent at the API, ask it to find downward-trending topics and draft procedures. It works.

LLM Choice

The LLM is the reasoning brain. ElevenLabs gives you three paths — and you can swap them without rebuilding the agent.

Self-Hosted
ElevenLabs runs open models on their own GPU clusters. Lowest latency path. Good for high-volume deployments where API call costs compound.
Third-Party API
Claude, GPT-4, Gemini — called via their APIs. Use the model you already trust. Easy to swap as models improve.
Your Own LLM
Plug in any custom endpoint. For teams with fine-tuned models, proprietary data, or compliance requirements around data leaving their infrastructure.
The session recommendation: Start with a third-party API model you already know well. Once you have stable call volume and your procedures are working, evaluate whether self-hosted inference makes sense at your scale. Don't optimise LLM cost before you know what your agent actually does in production.
Your Path

Get Started — The Recommended Journey

The session presenter walked through how ElevenLabs recommends you build — from the self-serve platform through to a production agent that improves itself. Not a waterfall. A loop: build, run, learn, refine.

Stage 1
Try it in the dashboard
The ElevenLabs platform has a self-serve tier. No forward-deployed engineer needed. You can have a working voice agent in under 10 minutes.
  • Write a system prompt and first message
  • Pick a voice from the library (or upload an IVC sample)
  • Choose your LLM — start with Claude or GPT-4 via their APIs
  • Call it. Hear it. Adjust the prompt.
→ Don't overthink the first agent. Get something speaking first, tune later.
Stage 2
Connect it to your data
A bare agent is a blank slate. The value comes from wiring it to what your business already knows.
  • Add a knowledge base for RAG over your docs
  • Wire webhooks to your existing APIs (CRM, ticketing, booking)
  • Or use native integrations for one-click platform connections
  • If you have an existing chatbot — try Speech Engine instead of rebuilding
→ MCP servers also work if you're already on that ecosystem.
Stage 3
Learn from real calls
Once calls are flowing, the platform gives you tools to find where the agent is failing — before your customers tell you.
  • Topic Discovery clusters your conversations semantically
  • Find clusters where sentiment trends downward over the call
  • Those are your gaps — where the agent is making things worse
  • Use Coaching to talk to the agent about a bad call and get its own suggestions
→ Claude Code pointed at the ElevenLabs API can read topics and draft procedures automatically.
Stage 4
Refine and ship safely
Every change to a production agent should go through a safety gate — even small ones. Voice agents are non-deterministic; surprises happen.
  • Write Procedures for the topics found in Stage 3
  • Run synthetic tests 10–50 times before any live traffic
  • Branch the change: 3% of real calls to the new config first
  • Compare sentiment and resolution rate across branches
→ This loop repeats. Stage 3 → Stage 4 is the continuous improvement cycle.
Who to involve: ElevenLabs has three access tiers. Self-serve for builders experimenting on their own. A growth team for teams scaling up. And forward-deployed engineers who embed directly inside enterprise customers to run the Stage 3–4 loop with them. The session presenter works on the agent platform and specifically supports the enterprise path — if you're building for regulated industries, that's the lane.
Reference

Abbreviations — Quick Reference for Newcomers

Every acronym used across this page and its companion, in one place.

STT Speech-to-Text Converts spoken audio into written words. The "ears" of a voice agent. Also called ASR.
TTS Text-to-Speech Converts written text into spoken audio. The "mouth." ElevenLabs V3 is their current flagship model.
ASR Automatic Speech Recognition Older term for STT. Same technology — you'll see both in ElevenLabs documentation.
LLM Large Language Model The reasoning brain — Claude, GPT-4, Gemini, or a self-hosted open model. Decides what the agent says next.
IVC Instant Voice Clone Upload 2–3 audio samples, voice clone ready in seconds. Best-effort quality. May not preserve accent.
PVC Professional Voice Clone Upload ~2 hours of audio. Near-indistinguishable from real voice. Requires identity verification. Paid tier.
IVR Interactive Voice Response The old "press 1 for billing" phone tree. What ElevenLabs voice agents replace with natural conversation.
RAG Retrieval-Augmented Generation Agent looks up a knowledge base before answering. ElevenLabs supports RAG over docs attached to an agent.
SOP Standard Operating Procedure Step-by-step guide for handling a specific situation. ElevenLabs "Procedures" are SOPs wired to trigger words.
API Application Programming Interface A standard way for software to talk to software. ElevenLabs exposes APIs for STT, TTS, agents, and more.
SDK Software Development Kit Pre-built code libraries. ElevenLabs has SDKs in Python, JavaScript, WebSocket, WebRTC, React Native, and Kotlin.
OTP One-Time Password A short code sent by SMS or email to verify identity. Used in the bank authentication pattern covered in this page.
MCP Model Context Protocol Standard for connecting AI agents to external tools and data. ElevenLabs agents support MCP servers natively.
CRM Customer Relationship Management Salesforce, HubSpot, etc. Voice agents connect to these via webhooks or native ElevenLabs integrations.
WebRTC Web Real-Time Communication Browser-native protocol for real-time audio. One of ElevenLabs' SDK transport options — preferred for browser-based voice.
